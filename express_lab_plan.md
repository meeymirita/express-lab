# Node.js + Express Lab — план (ShareBox)

> Статус: **план утверждён владельцем 11.10.2026 (домен D2+D4+D1, размер «M и чуть больше», локально на Mac); решения по ТЗ — 12.10.2026 (админ, пароль на ссылке, файлы до 200 МБ, HTML-страница, подробное скачивание через консоль).** Методички и кода нет, ничего не проверялось. Подробное ТЗ — [`express_lab_tz.md`](express_lab_tz.md).

## Зачем лаба

В репозитории есть `nestjs`, `graphql`, `typescript`, но нет введения в сам **Node.js** и **Express**. NestJS-лаба просит «основы JS и Node», а объясняет только Nest. Nest работает поверх Express, и без Express непонятно, чем Guards / Pipes / Interceptors отличаются от обычных middleware.

Лаба закрывает пробел: **Node → Express → то, что потом скрывает Nest**. Идёт перед `typescript` и `nestjs`.

## Что строим

**ShareBox** (рабочее название) — файлообменник со ссылками: пользователь регистрируется, загружает файлы и отправляет другим короткую ссылку на скачивание.

| Часть | Что даёт |
|---|---|
| Пользователи, JWT, владение (D2) | регистрация, логин, свои файлы, чужие недоступны |
| Загрузка и скачивание (D4) | `multer`, потоки, лимиты, безопасность файлов |
| Короткие ссылки (D1) | код, срок жизни, лимит скачиваний, пароль, статистика |

Todo-сюжет из `test_express` не используется (неинтересен владельцу); оттуда берутся только приёмы (валидация, коды ответов, nodemon).

## Параметры

- **Размер:** 11 сессий по ~4 ч (≈ 42 ч), 6–8 шагов на сессию (≈ 75–85 шагов). Время ориентировочное; после прохождения в подписи сессии «автор за ≈ N ч» (как в Caddy).
- **Сложность:** лёгкая–средняя. Чистый JavaScript (ESM), без TypeScript.
- **Среда:** **Node 24 прямо на Mac** (без контейнера для кода). PostgreSQL 18 — в Docker Compose (только база), поднимается с сессии 5 и **только с согласия владельца** (Docker Desktop запускать только с её согласия). Если Docker не хочется — запасной путь: `brew install postgresql@18`.
- **Версии-стандарт:** Node 24 LTS, Express 5, PostgreSQL 18 (том монтируется в `/var/lib/postgresql`), Prisma 7 (`prisma@7`), Vite не нужен.
- **Формат и подробность:** по `plan/README.md` (правила 2 и 3): «слова шага», «где мы и что должно быть», «если не получилось», «сломать → починить», бюджет шага ≈ 2 тыс. знаков.
- **Режим:** самостоятельная, `starter/` не нужен. Методичка собирается генератором из Markdown (как Bash Lab, `tools/build-manual.py`).

## Сессии

| # | Тема | Что получается |
|---|---|---|
| 1 | Node с нуля | что такое Node и V8, модули CJS/ESM, `process`, npm-скрипты, `node:http` руками: первый сервер без фреймворка |
| 2 | Асинхронность и потоки | event loop на примерах, callbacks → promises → async/await, `EventEmitter`, **streams и Buffer**: копирование файла потоком |
| 3 | Express 5 | роутер, `req`/`res`, параметры и query, `express.json()`, порядок middleware, статика; каркас ShareBox, `GET /health` |
| 4 | Ошибки, валидация, структура | единый error handler, свои классы ошибок, zod, слои routes → controllers → services, `.env`, DI вручную |
| 5 | PostgreSQL и SQL | Docker Compose с базой, `pg`, пул, SQL руками, транзакции; таблицы users, files, shares |
| 6 | Prisma 7 | схема, миграции, клиент, переписываем слой данных; сравнение «`pg` руками vs Prisma» |
| 7 | Аутентификация | регистрация, argon2, JWT access/refresh, ротация refresh, middleware авторизации, владение ресурсом |
| 8 | Файлы | `multer`, файлы до 200 МБ потоком (память не растёт), лимиты и 413, случайные имена, MIME и path traversal, хранение на диске, скачивание потоком, `Content-Disposition`, `Range` и докачка |
| 9 | Share-ссылки и консоль | код ссылки, срок жизни (410), лимит скачиваний, пароль, счётчик и журнал; **HTML-страница скачивания**; **скачивание из консоли с нуля** (`curl`, `wget`, PowerShell, докачка, проверка sha256) |
| 10 | Админ и надёжность | роль admin и `/admin/*`, rate limit на публичные ссылки, helmet, CORS, pino-логи, graceful shutdown, health/ready, чистка просроченных ссылок и файлов |
| 11 | Тесты, Docker, финал | `node:test` + supertest, Dockerfile и compose для всего ShareBox, Caddy перед Express, «Production Hell» без подсказок, таблица «Express → NestJS» |

Каждая сессия: критерий приёмки («команда → ожидаемый вывод»), «Слова сессии», карточка-шпаргалка. В конце лабы: справка «симптом → причина → что делать», глоссарий, вопросы для собеседования, «что дальше».
