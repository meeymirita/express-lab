# Node.js + Express Lab

![Express Lab](https://raw.githubusercontent.com/meeymirita/works-lab/main/images/express.png)

Курс в двух частях. **Часть I — Node.js с нуля** (сессии 1–8): рантайм, протокол HTTP, свой сервер, процессы, архитектура, тесты — без языка JS, он предполагается пройденным в `js-lab`. **Часть II — Express** (сессии 9–19): роутинг, middleware, ошибки, база, JWT, файлы, тесты, Docker — и в конце таблица «что из этого скрывает NestJS». Два сквозных проекта: «Загрузчик страниц» (CLI на голом Node) и **ShareBox** — файлообменник со ссылками (до 200 МБ), расширенный в финале до командного пространства.

**Статус: ✅ переписана в две части 14.10.2026 (ассистентом); 19 сессий, 94 шага, весь вывод проверен настоящим прогоном в Docker (Node 24, PostgreSQL 18 для сессий 12–18, отдельный контейнер `sharebox-verify-pg`); владелец лабу ещё не проходила. Два открытых пункта — `fixes/backend/express.md`, раздел «Найдено, не починено».**
**Сложность: лёгкая–средняя.** **Пререквизит части I: `js-lab`** (язык там не повторяется).

## Что внутри

- **19 сессий, 94 шага, ~76 часов** (часть I ~32 ч, часть II ~44 ч). Часть I: Node и npm, файлы/Buffer/Streams, протокол HTTP и свой сервер, процессы и параллелизм, архитектура (слои, свои ошибки, zod), тестирование (моки/стабы), эксплуатационная граница (конфиг, graceful shutdown) → финал — «Загрузчик страниц». Часть II: Express 5 → REST и контракт API → ошибки/валидация на Express → PostgreSQL → Prisma 7 → JWT-аутентификация → файлы → share-ссылки → админка/наблюдаемость → тесты и Docker → финал — «ShareBox Teams» (командные пространства, роли, очередь импорта, webhook).
- В нескольких сессиях — шаг «🔨 Сломать → починить», в сессии 18 — «Production Hell» и сравнение Express → NestJS.
- Справка: шпаргалка, справочник ошибок (симптом → причина → что делать), глоссарий, вопросы на собеседование, «что дальше» — все обновлены под новую нумерацию.
- Режим: самостоятельная лаба, но с пререквизитом `js-lab` для части I. Node нужен на Mac с сессии 1; PostgreSQL в Docker — с сессии части II про базу (12), только с согласия.

## Как пересобрать методичку

Из корня сборного репозитория `anitech-performance`:

```bash
python3 tools/build-manual.py express --run   # выполнить блоки ```bash run в Docker и собрать
python3 tools/build-manual.py express         # собрать из сохранённых выводов (Docker не нужен)
python3 tools/build-manual.py express --check # только проверка структуры
```

Для сессий 12–18 (часть II с базой) одного `--run` недостаточно — нужен реальный PostgreSQL 18, доступный внутри check-контейнера как `localhost:5432` (подробности — `fixes/backend/express.md`, раздел «🧪 Инфраструктура проверки»).
