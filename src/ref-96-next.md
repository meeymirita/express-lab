# 5 · Что дальше | short: Что дальше | kind: ref
Ты собрала ShareBox — Node и Express с нуля, базу, авторизацию, файлы, share-ссылки, тесты и Docker. Что дальше:

- **TypeScript.** Весь код ShareBox — на чистом JavaScript; та же архитектура (роуты/контроллеры/сервисы, Prisma, zod) с типами перестаёт давать часть ошибок ещё до запуска. Естественный следующий шаг перед NestJS.
- **NestJS.** Декораторы, модули, DI «из коробки» — то, что в ShareBox собиралось вручную (слои, DI, валидация, обработка ошибок), в NestJS уже встроено как архитектура фреймворка. Полезно сравнить, какую часть ручного кода сессий 4 и 7 заменяет один декоратор.
- **GraphQL.** Альтернатива REST из сессий 3–10: один эндпоинт, клиент сам описывает, какие поля ему нужны — стоит сравнить с тем, как `/files`, `/shares`, `/admin/*` росли по отдельности.
- **Redis.** Rate limit из сессии 10.3 — в памяти процесса; в реальном проде с несколькими инстансами серверов его считают в общем месте — Redis этому и учит.
- **RabbitMQ / очереди.** Чистка просроченных ссылок (сессия 10.6) и, например, отправка email при регистрации — кандидаты на то, чтобы стать фоновым заданием в очереди, а не кодом внутри обработчика запроса.
- **Фронтенд (Vue/Nuxt).** ShareBox отдаёт голый HTML для страницы скачивания (сессия 9.4); настоящий клиент на Vue умел бы показывать список своих файлов и ссылок, а не только форму.
- **Углубление в Express/Node.** Официальные гайды Express по безопасности и производительности в проде; `node --prof` для профилирования; `AsyncLocalStorage` для контекста запроса без протаскивания параметров через все слои вручную.
- **Когда не Node.** Если нужна тяжёлая вычислительная нагрузка (не ввод-вывод) — однопоточность Node становится узким местом; стоит присмотреться к Go (воркеры, конкурентность) или языкам с настоящей многопоточностью.
