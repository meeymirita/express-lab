Node.js :: среда выполнения JavaScript вне браузера, построена на движке V8; даёт доступ к файлам, сети, процессам
V8 :: движок JavaScript от Google (тот же, что в Chrome): компилирует и исполняет код
event loop (событийный цикл) :: механизм Node, который по очереди обрабатывает готовые к выполнению колбэки, не блокируя поток на ожидании ввода-вывода
CommonJS :: старая система модулей Node: <code>require(...)</code> / <code>module.exports</code>
ES Modules (ESM) :: современная система модулей: <code>import</code>/<code>export</code>, требует расширение <code>.js</code> в пути и <code>"type": "module"</code>
колбэк (callback) :: функция, которую передают другой функции, чтобы она вызвала её позже — например, когда закончится чтение файла
Promise :: объект, представляющий результат асинхронной операции, который появится позже: «выполнен», «отклонён» или «в ожидании»
async/await :: синтаксис поверх промисов — асинхронный код выглядит как последовательный
EventEmitter :: объект, который может «испускать» именованные события и на которые можно подписаться через <code>on(...)</code>
поток (stream) :: способ обрабатывать данные порциями, не загружая всё в память целиком — нужен для больших файлов
Buffer :: кусок бинарных данных в памяти Node — то, чем оперируют потоки до того, как их превратят в текст
middleware :: функция в Express, которая получает запрос до (или вместо) обработчика роута и решает: пропустить дальше (<code>next()</code>) или ответить самой
роутер (router) :: объект Express, группирующий обработчики по путям и методам (<code>GET</code>/<code>POST</code>/…)
слои (routes → controllers → services) :: архитектурное разделение: роут знает про HTTP, контроллер связывает роут и логику, сервис не знает про <code>req</code>/<code>res</code> вообще
валидация :: проверка входных данных по схеме (zod) до того, как они попадут в бизнес-логику
пул соединений (connection pool) :: набор заранее открытых соединений с базой, которые приложение переиспользует вместо того, чтобы открывать новое на каждый запрос
транзакция :: группа операций с базой, которые выполняются как одно целое: либо все применяются, либо ни одна (<code>BEGIN</code>/<code>COMMIT</code>/<code>ROLLBACK</code>)
SQL-инъекция :: уязвимость, когда часть запроса к базе собирается из необработанного пользовательского ввода; закрывается параметризованными запросами
ORM (Object-Relational Mapping) :: инструмент, который представляет таблицы базы как объекты/классы в коде — Prisma в этой лабе
миграция (migration) :: файл, фиксирующий одно изменение структуры базы, применяемый по порядку, чтобы все окружения получили одинаковую схему
JWT (JSON Web Token) :: подписанный токен, в котором закодированы данные (например, id пользователя) и срок действия; подпись не даёт его подделать
access-токен :: короткоживущий JWT, который клиент присылает с каждым запросом
refresh-токен :: долгоживущий токен, обмениваемый на новую пару access+refresh, чтобы не логиниться заново каждые 15 минут
ротация токена :: при каждом обновлении выдаётся новая пара токенов взамен старой, а не продление старой
хеширование пароля :: необратимое преобразование пароля (argon2) перед сохранением — в базе никогда не хранится сам пароль
middleware авторизации :: проверяет токен из заголовка <code>Authorization</code> и кладёт данные пользователя в <code>req.user</code> для следующих обработчиков
владение ресурсом :: проверка, что пользователь действует со своими данными (своим файлом, своей ссылкой), а не чужими
path traversal :: атака через имя файла вида <code>../../etc/passwd</code>, пытающаяся выйти за пределы разрешённой папки
Range-запрос :: заголовок <code>Range: bytes=...</code>, которым клиент просит часть файла — основа докачки и перемотки видео
rate limit :: ограничение числа запросов за промежуток времени, после превышения — <code>429 Too Many Requests</code>
graceful shutdown :: корректное завершение процесса: доделать текущие запросы и закрыть ресурсы перед выходом, а не оборвать их
health check / readiness :: роуты, которыми внешняя система (оркестратор, балансировщик) проверяет, что приложение живо и готово принимать трафик
структурированные логи :: записи лога в машиночитаемом формате (JSON), а не произвольный текст — удобно искать и агрегировать
supertest :: библиотека для тестирования HTTP-роутов Express без поднятия сервера на реальном порту
node:test :: встроенный в Node тест-раннер, не требует отдельного пакета для базовых тестов
